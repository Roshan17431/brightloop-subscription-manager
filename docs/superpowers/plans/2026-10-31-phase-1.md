# Brightloop Phase 1 Implementation Plan

**Goal:** Runnable integrated subscription management foundation matching the supplied PDF and user scope.
**Architecture:** Java 21 / Spring Boot 4 modular monolith, PostgreSQL and Flyway, Next.js App Router client. Feature packages own DTOs, services and persistence. Server authorization is authoritative.
**Spec:** ../../Subscription_Management_System.pdf and user's Phase 1 implementation instructions.

## Decisions
User explicitly requested immediate implementation using locked stack; proceed without a further design approval gate. Native repository is empty and uses codex/phase-1. Preserve primary PDF in docs. No billing simulation. Plan prices are independent metadata; product sales prices plus variant adjustment determine initial line unit prices. Tax rate on lines is an explicit Phase 1 snapshot, not a tax rules engine. Session cookie with CSRF protection; opaque hashed reset tokens sent via SMTP. Environment-only initial admin bootstrap.

## API contract (initial; superseded by expanded request)
The user expanded scope during implementation. `docs/phase-1-requirements.md`, `AGENTS.md` and `docs/api.md` supersede this initial contract: use `/api/v1`, full response envelopes, customer CRUD, role changes, plan products, and draft editing.

### Original planning baseline
All paths /api. Success {data: T}; errors {error:{code,message,details?}}. IDs numeric. Dates ISO YYYY-MM-DD. Amounts JSON numbers or decimal strings. Paginated data {content: T[],totalElements,totalPages,number,size}.
Auth: GET /auth/csrf -> {token,headerName}; POST /auth/register {name,email,password}; POST /auth/login {email,password}; GET /auth/me -> {id,name,email,role}; POST /auth/logout; POST /auth/forgot-password {email}; POST /auth/reset-password {token,password}. Credentials included in fetch; CSRF header from csrf endpoint on mutations.
GET /customers?q=&page=&size=; POST /staff {name,email,password} admin-only.
Products: GET /products paginated (q/page/size), POST /products, GET/PUT/DELETE /products/{id}; fields id,name,type,salesPrice,costPrice,notes,variants:[{id?,name,priceAdjustment}]. Catalog writes admin only; reads authenticated.
Plans equivalent CRUD: id,name,price,billingPeriod DAILY/WEEKLY/MONTHLY/YEARLY,minimumQuantity,availableFrom,availableUntil,automaticClosing,earlyClosingAllowed,pausingAllowed,renewalAllowed.
Subscriptions: GET /subscriptions?q=&page=&size=; POST /subscriptions {customerId? (self for customer),planId,startDate,expiryDate,paymentTerms,lines:[{productId,variantId?,quantity,taxRate}]}; GET /subscriptions/{id}; POST /subscriptions/{id}/transition {state}. Response id,number,customerId,customerName,planId,planName,startDate,expiryDate,paymentTerms,state,total,lines [{id,productId,productName,variantId,variantName,quantity,unitPrice,taxRate,amount}]. Customer only sees own; staff/admin manage transitions. Strict sequential states DRAFT QUOTATION CONFIRMED ACTIVE CLOSED. Dashboard derives counts from real lists; no revenue claims.
